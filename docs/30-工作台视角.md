# 30 · 工作台视角（打开就该知道做什么）

> **一句话**：v2.9.0 之前，看板是「账本的只读列表」；v2.10.0 起，看板是「账本驱动的工作台」——先给结论和入口，明细按需下钻。

## 一、为什么要突破原框架

前几版把导航、搜索、体验、架构图、数据流逐项补齐，但用户打开后仍要自己回答三个问题：

1. 现在最需要处理什么？
2. 这份账本可信吗？
3. 下一步该走哪条能力？

列表视图回答不了这三个问题。它擅长「查有没有」，不擅长「决定先做什么」。因此本版不再以「全部条目」为默认落点，而是把工作台作为首页。

## 二、改了什么

### 1. 默认落点 = 工作台

`let view='workbench'`。首屏导航第一位是「工作台」，「全部条目」收进「更多视图」。这是信息架构的调整，不是多挂一个标签。

### 2. 今日焦点（结论先行）

三张卡片从账本实时复算：

| 卡片 | 数据源 | 处理入口 |
|---|---|---|
| 阻塞 | `work_items` 里 `status=blocked` 的 issue | 工作项 |
| 失败用例 | `test_results.cases` 里 `fail` / `error` | 工作台明细 |
| 证据待补 | 能力点 `evidence_tier!=='verified'` | 能力地图 |

卡面只给数字和一句动作，不堆字段。

### 3. 可信度条

第一眼可见：证据新鲜度、`verified / 总能力点`、整体完成度、测试报告绑定摘要、数据来源徽标。项目主张是「诚实 > 绿灯」，因此这些数字不能再藏在工作台深处。

### 4. 入口矩阵

把工作项、架构图、数据流、能力地图、术语与实现、设计理念做成六张可点击卡片，各带实时计数。原 14 个 `data-v` 一个不删，但从「平铺标签」变成「从工作台下钻的入口」。

### 5. 下一轮队列与焦点队列

- 下一轮队列由 SELECT 从证据缺口派生，按完成度升序；每张任务卡带节点工作条 `workStripHtml(t.code)`。
- 焦点工作项按阻塞 → issue → 高优先级 → 普通 TODO 排序。
- 搜索现在对工作台的焦点、任务卡、工作项、失败用例、证据待补生效；架构图 / 数据流中的节点命中后高亮描边。

### 6. 来源与窄屏

- 上下文条和页脚标明数据来自「内嵌快照 / 实时 JSON / 离线快照」；同目录账本加载失败不再静默。
- SVG 外层加横向滚动容器并设最小宽度，窄屏不再把 10px 文字压成 4px。

## 三、守住的边界

- **不造第二事实源**：焦点、可信度、队列、入口计数全部从 `DATA` / `ONTO_TERMS` 派生；不新增账本字段。
- **权威模板唯一**：只改 `templates/index.html.template`，再由 `board_contract.normalize --approved-by … --apply` 推到方法仓与示例看板。
- **骨架契约不变**：`stats` / `legend` / `list` / `foot` / `q` 锚点、`PAGE_SIZE=200`、全部 `data-v` 均保留，`scale_budget` 口径不变。
- **写盘需批准**：归一化与升级默认 dry-run，`--apply` 必须带批准人。
