# 36 · 风险下降判据（v2.19.0）

运行时信号把 STATE 事件投影成 `risk_score` 并驱动 `next_queue` 排序（见 34）。
v2.18.0 给信号加了时间衰减：陈旧信号分数下降、到 7 天过期出队。但这带来一个
**必须显式澄清的语义陷阱**——分数下降有两种完全不同的来源，混为一谈就是假绿灯。

## 两个正交维度

| 维度 | 来源 | 随时间 | 代表什么 |
|---|---|---|---|
| 风险严重度（severity） | 客观指标（污染率、断供状态、seam 比例） | 不因时间自动下降 | 风险本身有多严重 |
| 信号新鲜度（freshness） | 事件观测时刻 | 线性衰减，7 天过期 | 这条信号还值不值得排在队首 |

当前 `risk_score` 把两者乘在一起：`severity(0.5~1.0) × decay_factor`。
于是出现一个危险现象：**一个"单调上升"的风险（severity 满格），只因为观测久了，
分数也会下降**。看板读者看到 `1.0 → 0.8571` 会以为风险在改善，而原文指标其实在恶化。

> 事实：E4 的 `risk_score` 因衰减从 1.0 降到 0.8571；同一份原文里 HK seam 是
> 27.3% → 31.7% → 31.9% → 32.24%，单调上升。分数下降与风险走势方向相反。

## 判据：什么才算"风险下降"

风险下降必须同时满足四条；任何一条不满足，只能说"信号变旧"，不能说"风险下降"。

1. **同主体**：后续观测与原始信号针对同一风险主体（同一 symbol / 域 / 能力点）。
   拿别的母体或别的指标数字冒充下降，不成立。
2. **同口径**：指标定义、单位、方向语义不变（"越高越危险"不能中途变成"越低越危险"）。
3. **方向改善且持续**：数值朝安全方向变化，且至少两个后续观测点；单点是噪声，不是趋势。
4. **人工裁决关闭**：最终"风险已关闭"必须作为账本决策条目写入（operator 批准），
   观察器只提供证据，绝不自动关闭。

## 禁止项（fail-closed）

- **衰减 ≠ 下降**：`decay_factor` 下降只说明信号陈旧、需要重新观测，不说明风险变小。
- **跨母体 ≠ 下降**：不同口径的两个数相减（如 frontier 闸口 vs membership 分母）没有意义。
- **单点 ≠ 趋势**：一个观测点不能判定方向。
- **猜指标 = 误挂**：原文里混杂多种百分比（seam、健康度、symbol 级别），观察器不得猜测
  哪个是风险指标；抽不出显式、连续、同口径的序列就返回空（与映射层的 fail-closed 一致）。

## 只读观察器

`runtime_signals.py` 新增两个纯函数，供报告与人工裁决使用：

- `extract_metric_trend(signal)`：从 `finding`/`evidence` 抽取连续的 `a → b → c` 数值序列，
  返回 `{values, unit, direction, first, latest, delta, source_field}`；抽不出返回 `None`。
- `risk_outcome(signals, as_of, decisions=None)`：对每个信号观察其指标方向，与衰减方向对照，
  输出 `decay_vs_metric`（`divergent` = 分数降但指标恶化，需警惕 / `aligned` / `n/a`）；
  传入 `decisions` 时附加 `disposition`。
- `signal_disposition(signal, decisions)`：判定信号是否已被账本决策显式关闭（见下）。

全部**只读、不写盘、不下"风险已下降"结论、不回写账本**。权威事件仍在
`projects/*/state/events`，能力模型仍在 `governance/DECISION_LEDGER.json`。
主仓入口 `governance/risk_outcome.py --as-of <ISO8601>`（`--as-of` 必填带时区，
默认读账本判关闭状态，`--no-disposition` 可只看指标/衰减）。

## 关闭回路：引用 ≠ 关闭

风险关闭必须由**账本决策显式表达**，复用既有决策条目 schema，不新增事实源或字段。
`signal_disposition` 的判定（三条同时满足才算 `adjudicated_closed`）：

1. 决策 evidence 含指向本信号的 `*.md#E<n>` 引用（source_file + id 双匹配）；
2. 决策 status ∈ `{done, decided, approved}`（`proposed/deferred/superseded` 不算）；
3. decision/title 含**显式关闭意图标记**（如"关闭风险"/"风险关闭"/"close risk"）。

第 3 条是防假绿灯的关键：D-023 引用了 E4，但原文写"不关警报"——判 `open`（正确）。
若把"有决策引用"当作"已关闭"，就会把一次补证据决策误读成风险关闭。fail-closed：
猜不出关闭意图就当未关闭。

关闭回路至此完整：观察器把"分数降/指标升/是否关闭"三件事分开呈现，operator 依据
客观序列裁决，裁决写入账本决策后，`disposition` 才转为 `adjudicated_closed`。
观察器本身**永不自动关闭**。

## 已知残差

- E4（HK seam 单调上升）仍 open：衰减不构成风险下降；D-023 虽引用 E4 但明写不关警报，
  判据正确地判其未关闭。真正关闭须先按 symbol 固定 canonical source 降低 seam，
  再由 operator 写入带关闭意图的账本决策。
- E1（collapse 守卫母体不一致）仍 open / owner=operator：属行为缺陷，不是补证据任务。
- 本判据只定义"如何诚实呈现与记录裁决"，不替代人对真实风险的处理。
