# 10 · AI 集成：专家与技能

这套方法最终要被 AI 消费。为此提供两类可复用资产：一个**专家**（定义角色与纪律）和五个**技能**（定义动作与接口）。它们是纯文本，既能装进 WorkBuddy，也能作为任意 Agent 的 system prompt / tool spec 使用。

## 一、资产清单

| 资产 | 位置 | 职责 |
|---|---|---|
| 专家 `ledger-steward` | `experts/ledger-steward/EXPERT.md` | 角色、权限矩阵、写入纪律、输出模板、停止条件 |
| 技能 `ledger-scan` | `skills/ledger-scan/SKILL.md` | 重跑生成器，刷新能力/历史/候选/任务队列 |
| 技能 `ledger-verify` | `skills/ledger-verify/SKILL.md` | 18 条不变量 + 失败修复表 |
| 技能 `ledger-decide` | `skills/ledger-decide/SKILL.md` | 从任务卡写 `proposed` 决策 |
| 技能 `ledger-lesson` | `skills/ledger-lesson/SKILL.md` | 确认 / 驳回经验候选 |
| 技能 `ledger-guard` | `skills/ledger-guard/SKILL.md` | 统一门禁，一条命令全量验证 |

## 二、安装到 WorkBuddy

```bash
# 技能：复制目录到用户级 skills
cp -r skills/ledger-scan skills/ledger-verify skills/ledger-decide \
      skills/ledger-lesson skills/ledger-guard \
      ~/.workbuddy/skills/

# 专家：把 EXPERT.md 作为专家包主体；或在会话中直接作为角色提示词加载
cp -r experts/ledger-steward ~/.workbuddy/experts/
```

技能使用标准 `SKILL.md` frontmatter（`name` / `description` / `metadata`），与 WorkBuddy 现有技能格式一致。`description` 中的中英文触发词决定何时被调用。

## 三、平台无关的接入方式

不使用 WorkBuddy 的 Agent 也能接：

1. 把 `EXPERT.md` 正文作为 system prompt；
2. 把五个 `SKILL.md` 的「输入 / 输出契约 + 步骤」作为工具描述；
3. 工具实现就是仓库里的脚本：`build_capability_model.py` / `verify_ledger.py` / `scripts/ledger_decide.py` / `scripts/ledger_lesson.py` / `scripts/check.sh`。

所有工具都是标准库 Python 或 shell，无 MCP、无网络、无密钥依赖。

## 四、最小消费路径

一个编码代理接手迭代，只需读三样东西：

```
DECISION_LEDGER.json
├── capability_model.next_queue   ← 一条任务：code / 等级跃迁 / 缺什么证据 / 关联文档 / 相关经验
├── lessons.items                 ← 已确认经验（任务卡已按 scope 附好，无需另查）
└── history.events                ← 该能力做过什么变更（可回放）
```

执行顺序：

```
ledger-scan → ledger-verify → 取 next_queue 一条 → 补证据
→ ledger-scan → ledger-verify → ledger-lesson（若有新经验）
```

任何 `verify` 失败立即停止，先修账本。

## 五、权限边界（给 Agent 的硬约束）

- 可读：账本、历史、经验、源码、文档；
- 可写：`entries` 的新 `proposed`、`lessons.items`、驳回理由；
- 禁止：手改 `level` / `completion` / `history.events` / 看板 `EMBED`；禁止直接把 `proposed` 改成 `done`；禁止替人决定业务优先级。

这些边界同时写进 `EXPERT.md` 与各技能，并由 `ledger_decide.py` / `ledger_lesson.py` 在代码层强制——不依赖 Agent"记得遵守"。

## 六、验证 Agent 是否真的按纪律工作

`tests/test_skills.py` 用负向用例证明纪律生效：重复立项被拒绝、`confirmed` 缺 `action` 被拒绝、驳回无理由被拒绝。跑法见 [循环协议](05-循环协议.md) 与 `bash scripts/check.sh`。
