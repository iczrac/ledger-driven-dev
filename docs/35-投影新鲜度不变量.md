# 投影新鲜度不变量

健康度是账本的分析投影，不是独立事实源。它必须从 `test_results`、能力状态和
`work_items` 逐字段重算；任何手填都可能把看板变成第二套判定。

## 问题

`sync-tests` 会把 `governance/test_report.json` 的可验证投影写入账本
`test_results`。若之后没有重跑生成器，`capability_model.analytics.health.dimensions.test_pass_rate.detail`
会停留在旧分子/分母。分数可能仍是 100%，但投影已经不再忠实于证据。

## 规则

第 31 条不变量 `analytics_test_results_detail_valid` 採双向 fail-closed：

- 未启用 `test_results` 或分析层时判 `na`；
- 有合法非空 `cases`：`status=ok`、`score=half_up(100×passed/total)`、
  `detail=f"{passed}/{total}"`，且 `summary.total/passed` 相符；任何 `n/a` / `null` 皆 fail；
- `test_results` 缺失、`cases=[]`：`status=na`、`score=null`、精确 detail `n/a (未投影)`；
  若 `test_results` 为 dict，`summary.total=0` 且 `passed=0` 仍须成立；旧 `0/0`、假 `x/y` 与
  数值 `0` 一律 fail；
- `test_results` 为 dict 但 `cases` 非 list / schema 非法：直接 fail，不降级为 `na`；
- 第 28 条同步校验 `na_dims` 与 score=null 集合、以及由 `ledger/model` 重算出的 na 集合一致，
  防止把有资料维度手改成 `na` 灌高分数；
- 任一不一致即 `fail`，`--strict` 返回非零，禁止进入发版门禁。

## 纪律

修法只有一种：按当前测试报告重跑生成器，再提交账本。不得直接手改 `detail`，
也不得为了让验证器闭嘴而删掉 `test_results`。
