# 05 · 循环协议

账本不只是给人看的档案，更是驱动 AI 迭代的输入。循环协议定义了「如何把账本变成下一轮开发任务」。

## 六步循环

```
SCAN ──> SELECT ──> PLAN ──> EXECUTE ──> VERIFY ──> VISUALIZE
  ↑                                                    │
  └────────────────────────────────────────────────────┘
```

### 1. SCAN（扫描）

重跑生成器，按证据重算每个能力点的 `level` / `completion`。

- 触发时机：每次代码、测试、文档变更后；
- 产出：最新的 `capability_model`；
- 同时：对派生状态计算指纹，只有真实变化才向 `history.events` 追加一条事件（重跑不产生噪音），并刷新 `lessons.candidates`。详见 [09-历史与经验](09-历史与经验.md)。

### 2. SELECT（选择）

从能力点里筛选下一轮目标：

- 条件：`next_level > level` 且 `completion` 最低；
- 优先级：按完成度升序，同级按编码排序——**稳定可复现**，不靠人的临场判断。

**这一步已机器化**：生成器每次重跑都会把结果写入 `capability_model.next_queue`，按完成度升序排列。每条任务包含：

```json
{
  "rank": 1,
  "code": "DEMO.API.QUERY.01",
  "level": "L2", "target_level": "L3",
  "action": "tests/unit/ 有对应测试",
  "missing_evidence": ["契约(L1)", "单测(L3)", "测试记录(L4)"],
  "docs": { "plans": [...], "impl": [...], "unit_tests": [...] },
  "decisions": ["D-002"]
}
```

`next_action` 与 `missing_evidence` 精确告诉你缺什么证据；`docs` 直接给出要读的文档；`decisions` 关联到「为什么」；`lessons` 携带按 scope 匹配的已确认经验——不仅知道缺什么，还知道前人踩过什么坑。拿到一条就能开工——这就是 SELECT 从文字规则变成可执行接口的意义。

### 3. PLAN（规划）

为目标能力在账本 `entries` 新增一条 `proposed` 决策：

- `category` 填「能力建设」；
- 正文引用能力编码（如 `DEMO.CORE.PRICE.02`）；
- `next_action` 指明要补哪一级证据（来自能力点的 `next_action` 字段）。

**一个能力点一个决策**，避免散装任务。

### 4. EXECUTE（执行）

AI 或人按决策补齐证据：实现代码 + 契约 + 单测 + 测试记录，逐级补 L1→L4。

### 5. VERIFY（验证）

两层验证，缺一不可：

**第一层：账本自洽（可信）。** 运行 `verify_ledger.py --strict`，检查 31 条不变量——除编码/完成度/路径/决策引用/取代链/看板同步外，还包括历史链连续且指纹前后衔接、事件指纹自证、末事件与当前状态一致、经验条目合法且候选去重、任务卡只引用已确认经验。任何一条失败，说明账本已腐化，此时任何基于它的决策都不可靠，必须先修复。

**第二层：目标达成。** 重跑生成器：

- 若等级达成目标 → 决策状态从 `proposed` 流转到 `done`；
- 若未达成 → 记录阻塞原因，保持 `proposed` 或转 `deferred`。

> 为什么需要第一层？一套声称「证据驱动」的系统，自身若不可验证就是空谈。invariants 把「可信」从口号变成机器可执行的检查——这是整个方法能长期成立的地基。详见 [08-可信性校验](08-可信性校验.md)。

### 6. VISUALIZE（可视化）

看板自动反映新等级、完成度与索引，无需手工改图。回到 SCAN，形成闭环。

## 图模型（供自动编程消费）

能力模型天然是一张图：

- **节点**：每个能力点（code 为主键）；
- **边**：
  - `belongs_to`（模块 → 项目）
  - `implements`（能力 → 模块）
  - `supersedes`（决策取代链）
  - `depends_on`（规划依赖）

任何读取账本的规划器或编码代理，都能按 code 定位节点、按 `next_action` 生成任务、按 `doc_index` 找到要读的文档。

## 四条不变量

1. 编码稳定不复用；废弃标 `retired` 不删；
2. 完成度只由证据判定，禁止手填；
3. 每个 `next_action` 必须对应一个具体的等级证据要求；
4. 决策与能力双向引用——决策证据含能力 code，能力可回溯决策。

## 接入 AI 编码代理的最小清单

一个 AI 代理要接手迭代，只需要：

1. 读 `DECISION_LEDGER.json` 的 `capability_model.next_queue`（SELECT 已机器化）；
2. 取一条任务，读它的 `doc_index` 与 `lessons` 了解上下文、关联决策和前人经验；
3. 按 `next_action` / `missing_evidence` 补证据；
4. 重跑生成器验证等级是否提升，并查看 `history` 中新增的变更事件；
5. 若发现可复用规律，把 `lessons.candidates` 确认成 `items`，下一轮任务自动携带。

这就是「图像化自动编程」的可落地形态——不是让 AI 看截图，而是让它消费一份结构清晰、证据可追溯的图。
