# 31 · 可视化分析层：从看板数字到工作台判断

v2.11.0 把看板从「展示存量」推进到「支持判断」。新增的分析层不是第二事实源，而是从
`DECISION_LEDGER.json` 与既有历史快照只读派生的一组投影；前端只负责画图和内存模拟。

## 1. 数据契约

`capability_model.analytics` 的可选 schema 为 `maturity-analytics/1`：

| 字段 | 含义 | 来源 |
| --- | --- | --- |
| `maturity[code].series` | 每个能力点的 L0–L5 时间序列 | `history.events[].state_digest` |
| `change_summary` | 与前一事件快照相比的等级迁移、增删、证据变化 | `diff_state()` |
| `health.dimensions` | 证据新鲜度 / 测试通过率 / 决策积压 / verified 覆盖 / 工作健康 | 账本现有字段 |
| `recommended_actions` | 按健康度边际增益排序的下一步动作 | 同一套健康公式模拟 |
| `next_queue[].health_impact` | 该任务完成后预计提升的健康度分数 | 推荐行动映射 |

`summary.health_dimensions` 与 `summary.health_overall` 是同一投影的快捷入口，便于脚本消费。
旧账本没有 `analytics` 时，看板用 `deriveAnalytics()` 在浏览器内降级派生，不报错、不写盘。

## 2. 健康度公式

五个子维度先归一化到 0–100，再按固定权重相加：

- 证据新鲜度 20%：`fresh=100 / stale=50 / unbound=20`
- 测试通过率 25%：`pass / (pass + fail + error + 其他非通过)`，无用例记 0
- 决策积压 15%：`100 − min(100, 待裁决数 × 10)`
- verified 覆盖 20%：`verified / 能力点数 × 100`
- 工作健康 20%：`100 − min(100, 阻塞×20 + 其他Issue×8 + 失败用例×15)`

权重写在 `HEALTH_DIMENSION_WEIGHTS`，Python 与前端共用同一组数字；What-if 不能自带另一套判定。

## 3. 视图与触发方式

打开任意 `governance/index.html`（`file://` 即可），在导航或工作台入口矩阵中切换：

1. **能力热力图**：模块 × L0–L5 颜色梯度；顶部可切换「双层 / 仅 declared / 仅 verified」。
   点击能力格展开证据链。
2. **成熟度趋势**：从事件序号回放等级变化；最多展示 8 条有变化的序列，点击图例看证据链。
3. **任务卡片墙**：SELECT 队列，每张卡显示缺失证据、关联经验、健康增益；可直接假设补证。
4. **工作台**：可信度条下方新增五维健康度进度条。
5. **证据链钻取**：热力图 / 趋势 / 卡片墙里的能力点共用同一详情面板，含文档索引、变更历史与经验。
6. **变更高亮**：浏览器保存上次查看的指纹与工作项签名；指纹变化时，变化过的能力点与工作项加橙色标记。
   首次打开只记录基线，不误报。

## 4. What-if 模拟

上下文条点击「What-if 模拟」进入；也可在卡片墙直接点「假设补证」。

- 只克隆 `DATA` 到 `VIEW_DATA`，修改保存在 `whatIf.overrides`；
- 立即用同一公式重算健康度与任务卡增益；
- 退出模拟后 `VIEW_DATA` 回到原始账本快照；
- 全程不调用任何写入口，不产生文件改动，也不影响账本不变量。

## 5. 兼容与校验

- 旧账本：缺 `analytics` / `health_impact` 时判 `na`，看板降级派生，不判伪造。
- 第 28 条不变量 `analytics_maturity_valid` 校验：序列末点等于当前等级、分数在 0–100、
  加权和自洽、推荐行动与任务卡增益可追溯。
- 复验：`python3 governance/verify_ledger.py --root . --strict --json`。
