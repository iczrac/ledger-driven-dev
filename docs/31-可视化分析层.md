# 31 · 可视化分析层：从看板数字到工作台判断

v2.11.0 把看板从「展示存量」推进到「支持判断」。新增的分析层不是第二事实源，而是从
`DECISION_LEDGER.json` 与既有历史快照只读派生的一组投影；前端只负责画图和内存模拟。

## 1. 数据契约

`capability_model.analytics` 的可选 schema 为 `maturity-analytics/1`：

| 字段 | 含义 | 来源 |
| --- | --- | --- |
| `maturity[code].series` | 每个能力点的 L0–L5 时间序列 | `history.events[].state_digest` |
| `change_summary` | 与前一事件快照相比的等级迁移、增删、证据变化 | `diff_state()` |
| `health.dimensions` | 证据新鲜度 / 测试通过率 / 决策积压 / verified 覆盖 / 工作健康；每行含 `score` / `status` / `weight` / `effective_weight` / `detail` | 账本现有字段 |
| `health.coverage` | `applied` / `total` / `na_dims` / `weight_base`，揭露有效覆盖度 | 由 `status` 重算 |
| `recommended_actions` | 按健康度边际增益排序的下一步动作；覆盖不全时抑制并写 `recommendation_note` | 同一套健康公式模拟 |
| `next_queue[].health_impact` | 该任务完成后预计提升的健康度分数 | 推荐行动映射 |

`summary.health_dimensions` 与 `summary.health_overall` 是同一投影的快捷入口，
`summary.health_coverage` 是覆盖度的快捷入口；na 维度的 `score` 为 `null`，属预期值。
旧账本没有 `analytics` 时，看板用 `deriveAnalytics()` 在浏览器内降级派生，不报错、不写盘。

## 2. 健康度公式

五个子维度先归一化到 0–100：

- 证据新鲜度 20%：`fresh=100 / stale=50 / unbound=20`
- 测试通过率 25%：`pass / (pass + fail + error + 其他非通过)`；分母为 0 记 `n/a (未投影)`
- 决策积压 15%：`100 − min(100, 待裁决数 × 10)`
- verified 覆盖 20%：`verified / 能力点数 × 100`；能力点为 0 记 `n/a (无能力点)`
- 工作健康 20%：`100 − min(100, 阻塞×20 + 其他Issue×8 + 失败用例×15)`

分母为 0 的维度标 `status="na"`、`score=null`、`effective_weight=0`，detail 为上述精确字样；
`weight` 仍保留名义权重（向后兼容）。`overall` 用 `Σ(score × effective_weight) / Σ(weight for ok)`
重正规律，四舍五入统一 half-up（Python `math.floor` / 前端 `Math.round`），
无 ok 维度则 `overall=null`。Python 与前端共用同一组 `HEALTH_DIMENSION_WEIGHTS`，
What-if 不能自带另一套判定；两侧逐栏等价由 `tests/tools/compare_health_equivalence.py` 在 CI 比对。

呈现时不得把 na 当 0：健康检查点须和主分数相邻显示 `综合健康度（{applied}/{total} 維；測試未投影）{overall}`，
个别 na 维度显示 `n/a`、中色、进度条宽度 0；覆盖不全时推荐行动被抑制并显示原因。

## 3. 视图与触发方式

打开任意 `governance/index.html`（`file://` 即可），在导航或工作台入口矩阵中切换：

1. **能力热力图**：模块 × L0–L5 颜色梯度；顶部可切换「双层 / 仅 declared / 仅 verified」。
   点击能力格展开证据链。
2. **成熟度趋势**：从事件序号回放等级变化；最多展示 8 条有变化的序列，点击图例看证据链。
3. **任务卡片墙**：SELECT 队列，每张卡显示缺失证据、关联经验、健康增益；可直接假设补证。
4. **工作台**：可信度条下方新增五维健康度进度条。
5. **证据链钻取**：热力图 / 趋势 / 卡片墙里的能力点共用同一详情面板，含文档索引、变更历史与经验。
6. **变更高亮**：浏览器保存上次查看的指纹与工作项签名；指纹变化时，变化过的能力点与工作项加橙色标记。
   首次打开只记录基线，不误报。

## 4. What-if 模拟

上下文条点击「What-if 模拟」进入；也可在卡片墙直接点「假设补证」。

- 只克隆 `DATA` 到 `VIEW_DATA`，修改保存在 `whatIf.overrides`；
- 立即用同一公式重算健康度与任务卡增益；
- 退出模拟后 `VIEW_DATA` 回到原始账本快照；
- 全程不调用任何写入口，不产生文件改动，也不影响账本不变量。

## 5. 兼容与校验

- 旧账本：缺 `analytics` / `health_impact` 时判 `na`，看板降级派生，不判伪造；
  旧健康投影缺 `status` / `coverage` 时按名义权重旧公式处理，不追加新义务。
- 第 28 条不变量 `analytics_maturity_valid` 校验：序列末点等于当前等级、名义权重不变、
  `status` 合法、`na` 必须 `score=null` 且 `effective_weight=0`、按有效权重 half-up 重算 overall、
  `na_dims` 与由账本重算及 score=null 集合双向一致、推荐行动与任务卡增益可追溯。
- 第 31 条不变量 `analytics_test_results_detail_valid` 双向 fail-closed：有 cases 必为 ok 且
  detail=`passed/total`；无 cases 必为 na 且 detail=`n/a (未投影)`；schema 非法直接 fail。
- 复验：`python3 governance/verify_ledger.py --root . --strict --json`。
