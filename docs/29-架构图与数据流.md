# 29 · 架构图与数据流（让结构也能被看见）

> **一句话**：看板不该只列条目，还要回答「这些东西从哪里来、经过谁、流到哪里去、现在有多少」。v2.9.0 把架构与数据流做成账本驱动的图形，而不是手写装饰图。

## 一、为什么需要图

v2.8.0 解决了导航降噪、状态可见与搜索可达，但用户仍要自己在脑子里拼三层关系：

1. 账本、生成器、投影、视图之间到底谁依赖谁；
2. 一条决策/能力/术语从权威源到界面经过了哪些转换；
3. 每一层当前有多少数据——数字是不是和组织现状同步。

文字列表能回答「有什么」，图才能回答「怎么连」。但图一旦手画，就会变成第二事实源：账本更新了，图还停在旧版。因此本版的原则是：**图形也是投影**。

## 二、设计理念（界面可见）

「设计理念」视图列出七条原则，每条都带「为什么 / 界面落点 / 反例」：

| 原则 | 界面落点 |
|---|---|
| 单一事实源 | 页脚标注账本路径，所有计数从 `DATA` 派生 |
| 一屏一问 | 常用视图 7 项在前，治理/知识视图收进「更多视图」 |
| 状态可见 | 上下文条显示视图名、提示、搜索词与钻取作用域 |
| 计数即证据 | 统计卡、架构图、数据流节点均可下钻 |
| 渐进披露 | 卡片折叠、模块树、文档索引、批量展开/收起 |
| 双轨术语 | 机器分型词表与人读概念解说并列，不互相替代 |
| 可达与降级 | skip link / aria / 键盘 / 窄屏两列 / 离线内嵌数据 |

这组原则是呈现规则，不是账本事实：它只解释界面为什么这样组织，不存决策、能力或搜索结果状态。

## 三、架构图

`架构图` 视图渲染四层 SVG：

```
权威源 → 生成器 → 投影 → 视图
```

- **权威源**：决策账本、能力模型、本体投影、测试报告；
- **生成器**：`build_capability_model`、`board_contract`、`ontology.py`、`run_tests`；
- **投影**：`EMBED`、`ONTO_TERMS`、`work_items` / `test_results`；
- **视图**：工作台、能力地图、术语视图。

每个节点带当前计数（如「5 条决策」「11 能力点」「11 词」），点击节点跳到对应视图；键盘 `Enter` / 空格同样生效。节点不是硬编码文案，而是 `svgNode()` 从 `flowData()` 生成。

## 四、数据流 · 实时计数

`数据流` 视图渲染三条链路：

1. **声明链**：源码/测试/文档 → registry → 生成器 → 账本 → `EMBED` → 看板；
2. **写入链**：意图/路由 → 复述门 → 专家团编排 → 人工批准包 → 写入账本 → `history.events`；
3. **本体链**：`ONTOLOGY.json` → `ontology.py` → `ONTO_TERMS` → 术语视图，并与人读 `GLOSSARY` 并列。

每条边标注当前规模：决策条数、能力点数、工作项数、测试用行数、历史事件数、本体术语数。数字全部来自当前账本与 `ONTO_TERMS`；刷新账本后图形随之刷新，不产生第二份数据。

## 五、导航降噪

- 首屏只放 7 个高频入口：全部条目、工作台、工作项、待裁决、设计理念、架构图、数据流。
- 时间线、模块地图、架构钻取、能力地图、演进历史、经验库、术语与实现收进「更多视图」。
- 通过图节点或统计卡跳进隐藏视图时，`setView()` 自动展开「更多视图」，避免用户找不到目标。
- 全部 `data-v` 仍保留，测试与骨架契约不变。

## 六、守住的边界

- **不造第二事实源**：图形和理念都从账本/本体投影派生；理念只是 UI 文案。
- **权威模板唯一**：改图只能改 `templates/index.html.template`，再归一化到方法仓与示例看板。
- **数据段隔离**：`EMBED` 与 `ONTO_TERMS` 仍是唯一数据入口，图形只读它们。
- **契约锁定**：`tests/views/test_board_views.py` 检查理念/图/数据流锚点，并在无数据 DOM stub 中真实执行三个新渲染函数。

## 七、复算验证

```bash
python3 -m unittest discover -s tests -p 'test_board_views.py' -v
python3 scripts/board_contract.py --target . check --json

```
