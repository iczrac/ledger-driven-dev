# 28 · 看板体验（从看得见到用得顺）

> **一句话**：治理看板不是给生成器看的 JSON 外壳，而是人每天用来判断「现在该做什么」的工作台。v2.8.0 只改呈现层，不新增账本字段、不改判定规则。

## 一、为什么改

v2.7.0 已让账本真实自举、看板术语接上本体投影，但实际使用时仍有四处摩擦：

| 摩擦 | 旧表现 | 新处理 |
|---|---|---|
| 找不到当前状态 | 10 个视图平铺，切过去后不知道自己在哪里、搜了什么 | 顶部上下文条显示视图名、用途、搜索词、钻取作用域 |
| 统计只能看不能用 | 统计卡是死数字，看到「待裁决 3」还要自己找入口 | 统计卡变成跳转按钮，直接落到对应视图 |
| 搜索容易卡住 | 输入后没有明显清除入口，钻取后搜索词互相干扰 | 搜索框内清除按钮、`/` 聚焦、`Esc` 清除；上下文显示并可单独清除 |
| 长列表难扫读 | 卡片展开后没有收起状态，窄屏表格挤压 | 展开/收起带状态与文字，粘性导航、响应式两列、减少动态效果 |

## 二、改了什么

### 1. 结构语义化

- 增加跳转主内容的 skip link；`nav` / `main` / `footer` 替代裸 `div`。
- 视图按钮改 `button type="button"`，带 `aria-current="page"`；卡片展开按钮带 `aria-expanded`。
- 搜索、上下文条、列表容器加 `aria-label` / `aria-live`，读屏与键盘可用。

### 2. 当前状态可见

- `renderContext()` 从 `VIEW_META` 派生视图名、提示语与搜索占位符。
- 搜索词与钻取作用域显示成可移除 chip；「展开全部 / 收起全部」可批量操作卡片。
- 切换视图保留搜索词但清空钻取作用域，避免误以为数据丢失；点作用域链接进入工作项时清空搜索。

### 3. 操作路径缩短

- `stat()` 产出的统计卡支持 `data-jump`，由 `bindStats()` 事件委托统一跳转。
- 工作台里的 TODO / Issue / 失败用例 / 待裁决 / 健康度都能一键回到对应视图。
- `setView()` 统一处理高亮、`aria-current`、分页复位与回到顶部，避免每个入口各写一套。

### 4. 阅读舒适度

- 导航条 sticky + 毛玻璃背景；卡片 hover 有轻阴影；按钮有 focus-visible 轮廓。
- 小屏下视图横向滚动、搜索独占一行、统计两列、字段标签收窄。
- `prefers-reduced-motion` 关闭动画；打印时隐藏导航与操作区。

## 三、守住的边界

- **不造第二事实源**：`VIEW_META` 只描述视图标题、提示和搜索占位符，不复制账本状态，不参与判定。
- **源码仍是权威模板**：改样式只能改 `templates/index.html.template`，再由 `board_contract.normalize --approved-by … --apply` 推到方法仓与示例看板；项目内手改会被骨架摘要抓出。
- **数据段隔离**：`EMBED` 与 `ONTO_TERMS` 两段数据保持原范式；骨架摘要继续归一化两段，数据变化不触发版面漂移。
- **体验也被测试锁定**：`tests/views/test_board_views.py` 的 `test_board_ux_contract` 检查语义结构、上下文、搜索清除、统计跳转、响应式与降低动态效果的锚点；先红后绿。

## 四、可复算验证

```bash
python3 -m unittest discover -s tests -p 'test_board_views.py' -v
python3 scripts/board_contract.py --target . check --json
python3 scripts/board_contract.py --target examples/demo-shop check --json
python3 scripts/upgrade.py --target . verify --json
```

覆盖口径：模板骨架摘要一致、方法仓与示例看板同版、账本内 `governance_meta.board_skeleton` 绑定当前模板、UX 契约测试通过。
