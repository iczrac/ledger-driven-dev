# 26 · 来源投影与完成定义（Provenance View）

> **一句话**：把账本里已有的 `[AI推断]` 事实与 `[人确认]` 事实分组摊开给人看，
> 并从任务卡既有缺口派生「做到什么算完成」——**只读投影，不往账本加一个字段**。

## 一、为什么是投影，不是新字段

外部方法论（`ontology-driven-dev`）里最值得借鉴的一点，是让 AI 产出与人确认**可区分**。
但项目里这套区分**早就存在**：

| 语义 | 账本里的既有事实 | 谁控制 |
|---|---|---|
| `[AI推断]` | issue 的 `source=derived`、`derived_from`、`close_condition`、`status/severity`；decision 的 `status: proposed`、id/date | 生成器/门禁，重算覆盖 |
| `[人确认]` | issue 的 `owner`、`owner_note`、`detail`（重算保留）；decision 的 `title/decision/rationale/evidence/confidence`（人拍板，机器仅记录）；`status: done` | 人 + 生成器 |

若再加一个 `origin=ai-inferred/human-confirmed` 字段，就是**同一事实两处表达**——
正是单一事实源要避免的第二真相。所以本版走 ontology.py / work_panel.py 的
「只读投影」范式：`projection = f(账本)`，展示层重组，不落盘、不改结构、不参与写入链。

这也是 P2「不改治理规则」纪律的保证：27 条不变量不变、账本 schema 不变、
资产安装清单不变（新脚本只进 scripts 摘要）。

## 二、投影契约 `provenance-view/1`

```json
{
  "schema": "provenance-view/1",
  "issues": [{
    "id": "W-BIND-...",
    "ai_inferred": {
      "label": "[AI推断] 机器控制，重算覆盖，勿手改",
      "fields": { "source": "derived", "derived_from": {...}, "close_condition": {...} }
    },
    "human_confirmed": {
      "label": "[人确认] 人补充，重算保留",
      "fields": { "owner": "...", "owner_note": "...", "detail": "..." }
    }
  }],
  "tasks": [{
    "code": "...", "target_level": "L4",
    "criteria": ["契约(L1)", "测试记录(L4)"],
    "satisfied_when": "missing_evidence 为空且 evidence_tier=verified（v2.2.0 起 verified⟺bound）",
    "provenance": "从 target_level + missing_evidence 派生；非账本字段，不写回"
  }]
}
```

分组字段用**白名单**：机器字段与人工字段各一张表，只取存在的键，顺序稳定 → 可复算。

## 三、完成定义（definition_of_done）

任务卡原只给 `action`（下一步做什么）与 `missing_evidence`（缺什么），
没有一条可机读的「做到什么算完成」。投影把它补齐：

- `target_level`：目标成熟度；
- `criteria`：缺失证据项清单，逐条补齐即达标；
- `satisfied_when`：与 v2.2.0 硬门禁对齐——`verified⟺bound`；
- `machine_check`：`build_capability_model.py --check` 可复验。

这些都从既有字段派生，机器可判、人可复核，不写回账本。

## 四、用法

```bash
python3 scripts/provenance_view.py --target P --json           # 全部
python3 scripts/provenance_view.py --target P --kind issue     # 只看 issue 来源
python3 scripts/provenance_view.py --target P --kind decision  # 只看 decision 来源
python3 scripts/provenance_view.py --target P --kind task      # 只看完成定义
```

## 五、黄金范例（端到端可运行）

[examples/golden-walkthrough](../examples/golden-walkthrough/README.md) 把
复述门 → 路由 → 编排 → 批准包 → 来源投影 → 完成定义串成一条只读链：
`bash examples/golden-walkthrough/run.sh`，六步全过、两次逐字节一致、零写盘。
它同时演示 fail-closed：把意图换成未识别措辞，路由降为 low、编排拒绝展开——
**意图没被听懂，机器不往下走**。
