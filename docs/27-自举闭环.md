# 27 · 自举闭环（用 ledger 开发 ledger）

> **一句话**：方法论仓库必须用自己生产的账本治理自己——账本 = 真实开发历史。
> v2.7.0 之前这条链断了：账本停在 v2.3.0、无治理版本绑定、看板术语与本体脱节。

## 一、断链是怎么被发现的

一次只读检查问了三个问题，答案都是"没有"：

| 检查 | v2.7.0 前实况 |
|---|---|
| 账本记录后续发版了吗？ | entries 只有 1 条 `D-001 LEDGER · 治理初始化 · 建立账本与能力注册表（greenfield）`，v2.4/2.5/2.6 全没进账本 |
| 账本走升级迁移了吗？ | 无 `governance_meta`，`upgrade plan` 显示 `pre-1.0.0 → 2.6.0`（6 条迁移待做） |
| 看板术语来自本体吗？ | 「术语与实现」是模板内写死的 21 条概念，本体投影 11 条术语没人消费 |

根因：v2.4～v2.6 三次发版只改代码与文档（`git show --stat` 可证未碰 governance），
沿用"元工具不算能力点"的口径把它们排除在 registry 外——**没进 registry，
生成器就无从纳入；账本不重算，就留不住真实开发历史**。

## 二、A · 补自举的三层

账本要等于真实开发历史，必须三层都补齐，缺一层就是半自举：

1. **决策层**：三条发版决策补录为 `status=done`，证据指向真实 tag / 交付卡 / 实现脚本。
   走 `ledger_io.write_ledger` 唯一写入口（账本 + 看板 EMBED 同步），append-only，
   不碰 `history.events`（那是生成器维护的能力指纹链）。
2. **绑定层**：`upgrade apply --approved-by` 补齐 `governance_meta` 的五个绑定字段——
   `method_version` / `method_assets` / `board_skeleton` / `installed_assets` /
   `ontology_digest`（即 upgrade.py 里 AXIS_KEYS 声明的版本轴字段）。
   这些不是手填，是升级引擎按权威源码算出来的。
3. **能力层**：三个新元工具登记进 `registry.json`（显式 `code`，身份稳定），
   测试静态 import 实现 → 符号绑定判为 bound → verified。能力模型 7→10，
   `账本 = f(registry, 仓库, 报告)` 重新可复算。

守门测试 `tests/meta/test_dogfood.py`（6 条）锁定这三层，先红后绿：改之前 5 条失败，
实现后 6/6 全过。

## 三、B · 看板术语接本体（不替换，是并列）

本体的 `ubiquitous_language`（status/level/severity…）是**机器分型词表**，
看板原有 GLOSSARY（决策账本/能力点/可复算…）是**人读概念解说**——
语义层次不同，拿前者顶替后者是错的。正确做法是并列展示、明示来源：

- 权威模板新增第二数据段 `const ONTO_TERMS = [...]; let ONTO_DATA`（与 EMBED 同范式）。
- `board_contract.normalize` 从 `docs/generated/ONTOLOGY.json` 注入 11 条术语，
  骨架摘要归一化该段——本体内容变化不触发骨架漂移，老看板无该段也兼容。
- 「术语与实现」视图新增「本体投影词表」区，标注"机器派生，改权威源后重算"。
- `ledger_io.sync_board` 只替换 EMBED，不碰本体段——两个写入口职责分离，无冲突。

## 四、几条守住的纪律

- **不造第二事实源**：本体术语仍以 `ONTOLOGY.json` 为权威，看板只是它的展示投影；
  `governance_meta.ontology_digest` 只存摘要，不复制内容。
- **破坏性动作经人批准**：`upgrade apply` / `board normalize` 都带 `--approved-by`，
  写盘前自动备份到 `.ledger-upgrade/backups/`。
- **诚实 > 绿灯**：BINDING.07 负向探针仍是 declared/unbound，没有为凑满而伪造绑定。
- **fail-closed**：报告引用未入库文件时 freshness 拒绝采信、verified 全回落——
  新测试必须先 `git add` 入库才生成可信报告，这是自举必须付的代价。
