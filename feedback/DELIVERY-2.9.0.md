# DELIVERY 2.9.0 — 架构图与数据流：让结构成为可下钻的投影

- 版本：v2.9.0
- 日期：2026-11-20
- 状态：方法仓 dogfood 通过，全量门禁 EXIT=0；主项目推广待用户另行确认（只在干净 clone 操作）

## 一、为什么做这一版

用户反馈很直接：v2.8.0 虽然把导航、搜索、统计卡做顺了，但**体验仍缺设计理念，也看不到架构和数据怎么流**。缺的不是更多按钮，而是三件事：

1. 界面为什么这样组织，没有可见解释；
2. 账本 → 生成器 → 投影 → 视图的层级关系只能靠读代码；
3. 每条链路当前有多少数据，无法一眼确认是否与账本同步。

因此本版把「理念」和「结构」都做成看板的一部分，但坚持它们是**投影与说明**，不是第二事实源。

## 二、改了什么

### A · 设计理念可见

- 新增 `data-v="design"` 视图与 `DESIGN_PRINCIPLES`：七条原则，每条含「为什么 / 界面落点 / 反例」。
- 原则直接对应已实现行为：单一事实源、一屏一问、状态可见、计数即证据、渐进披露、双轨术语、可达与降级。
- 上下文条增加「设计理念」快捷入口；原则只描述呈现，不存账本事实。

### B · 架构图

- 新增 `data-v="diagram"` 视图，四层 SVG：权威源 → 生成器 → 投影 → 视图。
- 节点由 `svgNode()` 从 `flowData()` 生成，带当前账本计数；点击或键盘 `Enter` / 空格跳到对应视图。
- 边上标注「5 条决策 / 11 能力点 / 11 词」等实时规模，刷新账本即刷新图。

### C · 数据流 · 实时计数

- 新增 `data-v="flow"` 视图，三条链路同屏：声明链、写入链、本体链。
- 声明链展示源码/测试/文档 → registry → 生成器 → 账本 → EMBED → 看板。
- 写入链保留人工批准点：意图/路由 → 复述门 → 专家团编排 → 批准包 → 写入账本 → 历史。
- 本体链展示 `ONTOLOGY.json` → `ontology.py` → `ONTO_TERMS` → 术语视图，并与人读 `GLOSSARY` 并列。

### D · 导航降噪

- 首屏只保留 7 个高频入口；原 7 个治理/知识视图收进「更多视图」。
- 跳进隐藏视图时自动展开分组；全部 `data-v` 与骨架锚点保留，测试口径不变。

## 三、实证与关键数字

- 视觉契约 `test_board_visual_contract` 与空数据渲染探针先红后绿；三个新视图在无账本数据下也能渲染。
- 能力模型 11→12；11 verified + 1 declared（BINDING.07 负向探针继续诚实保留）。
- 全量门禁 EXIT=0、16 阶段；单测 378→379；`账本=f(registry,仓库,报告)` 逐字段可复算。
- 方法仓与示例看板骨架一致，看板 EMBED 与账本一致，升级复验 `upgrade_complete=true`。

## 四、守住的纪律

- **不造第二事实源**：图形、计数、理念全部是账本/本体投影；看板不回写事实。
- **权威模板唯一**：只改 `templates/index.html.template`，再归一化到方法仓与示例看板；项目内手改会被骨架摘要抓出。
- **数据段隔离**：`EMBED` / `ONTO_TERMS` 仍是唯一数据入口；图形只读它们。
- **写盘需批准**：看板归一化与升级都带 `--approved-by`，写前自动备份。
- **主仓不碰**：主项目工作区既有改动全程未动；v2.4～v2.9 推广仍待单独确认。
