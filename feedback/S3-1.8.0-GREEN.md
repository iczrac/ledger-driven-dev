## 三、重要的诚实纠正

早期内存验证曾报「降级数=0」，那是**把账本 cap code（`APEX.x`）与生成器输出 code（`RACOS.APEX.x`）当作同 key 比对**造成的假阴性——key 不同，所有降级都被漏掉。用剥离 project 前缀后重新对齐，真相是：

| 配方 | 正确对齐后的 level | 降级数 |
|---|---|---|
| 原 registry | L2:46 / L0:1 | **42** |
| 目录 + UT+TR hints（我早期误报为 0 的配方） | L5:20 / L3:14 / L2:13 | **8**（全是 ares/mind） |
| 本版实现（monorepo 目录 + 账本 hints + 正确门禁） | **L5:20 / L3:22 / L2:5** | **0** |

本版 `no_regress()` 用与账本同格式的 code 比较，不会再出现假阴性。此纠正写入
`feedback/ACCEPTANCE-1.8.0.md`，是「交付成果核实」纪律的一部分。
