# DELIVERY 2.10.0 — 工作台视角：打开就知道做什么

- 版本：v2.10.0
- 日期：2026-11-20
- 状态：方法仓 dogfood 通过，全量门禁 EXIT=0；主项目推广待用户另行确认（只在干净 clone 操作）

## 一、为什么做这一版

用户反馈：「从更工作台的角度出发，可以突破原有设计框架，但要有好的使用体验。」

前几版把看板做成了一个组织良好的账本列表：导航分组、搜索、体验契约、架构图、数据流都在。但列表的本质是「查」，不是「决定」。本版把默认落点从「全部条目」换成工作台，让看板先回答三件事：现在最需要处理什么、账本可信吗、下一步走哪条能力。

## 二、改了什么

### A · 默认工作台

- `let view='workbench'`；导航首位是工作台，全部条目移入「更多视图」。
- 原有 14 个 `data-v` 全部保留，但从平铺标签改为工作台入口矩阵的下钻目标。

### B · 今日焦点

- 阻塞 / 失败用例 / 证据待补三张结论卡，全部从 `work_items`、`test_results`、`capability_model` 实时复算。
- 每张卡带一个处理入口，点进去落到对应视图。

### C · 可信度条

- 证据新鲜度、`verified / 总能力点`、整体完成度、测试报告绑定摘要、数据来源徽标第一眼可见。
- 上下文条与页脚同步标注数据来自内嵌快照、实时 JSON 还是离线快照；加载失败不再静默。

### D · 队列、搜索与窄屏

- 下一轮队列由 SELECT 缺口派生，焦点工作项按阻塞优先。
- 搜索覆盖工作台各区；架构图 / 数据流节点命中后高亮。
- SVG 加横向滚动容器与最小宽度，窄屏不再压成不可读的小字。
- 批量展开 / 收起扩展到工作项、经验卡与 `<details>`。

## 三、实证与关键数字

- 契约测试 `test_board_workbench_contract` 先红后绿；三条新视图在空数据 DOM stub 中仍可运行。
- 新能力点 `METHOD.GOV.WORKBENCH.13`，能力模型 12→13。
- 全量门禁 EXIT=0、16 阶段；单测 381。
- 过程中发现并修复升级器的字符串版本比较缺陷：`2.9.0 > 2.10.0` 曾误判账本「来自未来」，已改为语义版本元组比较并补回归测试。
- 方法仓与示例看板骨架一致，看板 EMBED 与账本一致，升级复验 `upgrade_complete=true`。

## 四、守住的纪律

- **不造第二事实源**：所有焦点、计数、入口都从账本 / 本体投影派生；看板不回写事实。
- **权威模板唯一**：只改 `templates/index.html.template`，再归一化到方法仓与示例看板；项目内手改会被骨架摘要抓出。
- **数据段隔离**：`EMBED` / `ONTO_TERMS` 仍是唯一数据入口。
- **写盘需批准**：归一化与升级都带 `--approved-by`，默认 dry-run。
- **主仓不碰**：主项目工作区既有改动全程未动；v2.4～v2.10 推广仍待单独确认。
