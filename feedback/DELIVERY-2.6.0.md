# DELIVERY 2.6.0 — 来源投影与完成定义：借鉴而不造第二事实源

- 版本：v2.6.0
- 日期：2026-11-20
- 状态：方法仓 dogfood 通过，全量门禁 EXIT=0；主项目推广待用户另行确认（只在干净 clone 操作）

## 一、为什么做这一版

用户选 P2「方法论借鉴」，目标是「尽量全 AI 驱动」。评估外部方法论后，
唯一值得引入的是「让 AI 产出与人确认可区分」——但**不能照搬成新字段**。

第一性原理判断：项目里这套区分**早就存在**——
issue 的 `source=derived`/`derived_from`（机器控制、重算覆盖）与
`owner`/`owner_note`/`detail`（人补、重算保留）；decision 的 `status: proposed→done`。
再加一个 `origin=ai-inferred` 字段，就是同一事实两处表达，
违背 v2.2 以来死守的单一事实源。所以本版走「只读投影」而非「新增字段」。

七模型 YAML / 8 段硬暂停 / code-paas 一律不引入：
前者会成账本竞争的第二语义源，中段是要摆脱的瓶颈，后者本仓已用可复算脚本做得更严。

## 二、改了什么

- **`provenance_view.py`**（新增只读投影脚本，进 scripts 摘要，不进治理工具副本）：
  `projection = f(账本)`，把 issue/decision 既有字段按白名单分成
  `[AI推断]`（机器控制、勿手改）/`[人确认]`（人补、保留）两组展示；
  从任务卡 `target_level`+`missing_evidence` 派生 `definition_of_done`
  （含 `verified⟺bound` 达标条件与 `build_capability_model.py --check` 复验命令）。
  **不写回账本、不改 27 不变量、不参与写入链**。
- **黄金范例 `examples/golden-walkthrough/`**（可运行、可复算、零写盘）：
  `run.sh` 六步串起 复述门→路由→编排→批准包→来源投影→完成定义；
  配 `intent.json`（能力码锚定 demo 真实 code）与 `README.md`。
  放 examples 不进资产摘要，不触发额外整包安装。
- 新文档 `docs/26-来源投影与完成定义`；10 条单测（先红后绿）；
  版本 2.5.0→2.6.0；资产摘要 `7b629cec…`→`a8de309f…`（+脚本+文档）。

## 五、边界（诚实说明）

- **不改治理规则**：本版没有新增账本字段、没有改不变量、没有动专家/技能资产；
  `provenance_view` 是纯展示层工具，拿掉它治理链照常运转。
- **黄金范例的教学点**：意图换成未识别措辞（「补齐 … 测试记录」）会被 P0 的
  fail-closed 降为 low 并拒绝编排；范例用能命中的措辞，展示「听懂后才自治」的对照。
- **外部方法论只取一点**：可区分 AI/人来源；其余（七模型/硬暂停/code-paas）不引入。
- **主仓未碰**：用户工作区 100 个既有改动全程未动。本版只在方法仓发版。
- **整包升级待批准**：新增脚本+文档改变资产摘要，按 `method-assets` 纪律需所有项目
  重新批准升级；本次在干净 clone 验证可行，真正推广待用户确认。
